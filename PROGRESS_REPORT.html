Scalability Analysis Ceiling: ~1,000 Users

Current ceiling is approximately 1,000 concurrent active users before query performance degrades noticeably. The system will not survive 10k+ without the fixes below.
User CountStatusBottleneck
100 users
✓ Fine 		No issues. Supabase free tier + Vercel hobby handles this easily.
1,000 users
⚠ Degrading 		Full table scans on userId queries begin to show latency. List pages (TILs, snippets, bugs) load slowly for power users with 200+ entries.
10,000 users
✗ Painful 		No pagination means getTils(), getBugs(), getSnippets() fetch ALL rows into memory. OOM risk. Full table scans at scale cause multi-second queries. Supabase free tier connection pool exhaustion.
100,000 users
✗ System fails 		Without indexes, pagination, caching, and connection pooling at Supabase Pro level, the system would fall over. Vercel serverless functions would timeout under load from slow DB queries.

Root causes of scalability ceiling:

IssueImpactFix
No DB indexes on userId Every user query does a full table scan across ALL users' data Add index on userId on every content table (tils, bugs, snippets, flashcards, journals, roadmaps, session_logs)
No pagination List pages fetch every single row a user has ever created — unbounded memory Add limit + offset (or cursor) to all get* functions in crud.ts
N+1 queries in teams getTeam() runs 1 + N queries (one per member) instead of a single JOIN Rewrite to JOIN teamMembers ← profiles in one query
N+5 queries in inviteTeamMember() 5 sequential queries run for every invite (membership check, team lookup, seat count, invitee lookup, duplicate check) Combine into 2–3 queries with WHERE + COUNT in SQL
No FK constraints Deleting a Clerk user leaves orphaned rows in all tables — grows indefinitely Add FK constraints with ON DELETE CASCADE from profiles to all content tables
No composite indexes Heatmap and session analytics queries hit session_logs without a (userId, timestamp) index Add composite index (userId, startedAt) on session_logs

Important Technical Notes

Self-Healing DB Pattern: All schema changes use ALTER TABLE "table" ADD COLUMN IF NOT EXISTS ... inside ensureTablesExist(). This function runs once per server process (singleton promise pattern). New columns are safe to add — they run on first request after deploy. DB indexes should also be added here using CREATE INDEX IF NOT EXISTS. Never use drizzle-kit push/migrate commands on this project.
SM-2 Algorithm (Flashcards): easeFactor starts at 2.5. Again: ef -= 0.2, interval = 1. Hard: ef -= 0.15, interval × 1.2. Good: ef unchanged, interval × ef. Easy: ef += 0.15, interval × ef × 1.3. dueDate = today + interval days. New cards start with dueDate = now() so they're immediately reviewable.
PayMongo Webhook Verification: Header format: t=<unix_timestamp>,te=<hex_hash>. Signature: HMAC-SHA256(webhook_secret, "<t>.<rawBody>"). Must read request as raw text (not JSON) before verification. Bug B3: currently stores checkout session ID — should store subscription/customer ID for lifecycle management.
Stripe Webhook: Raw body must be read as Buffer.from(await req.arrayBuffer()). Do NOT parse JSON first or signature verification fails. Implemented in app/api/webhooks/stripe/route.ts.
Plan Inheritance for Teams: isPro() checks the user's own profiles.plan first. If 'free', it then checks team_members JOIN teams — if a team's subscriptionStatus is 'active', the member gets Pro-level access. Team subscriptionStatus is only set when the team owner pays for the Teams plan.
jsPDF — Browser Only: jsPDF v4.2.1 is installed but only works in the browser. Use await import('jspdf') inside a click handler. Never import in server actions or API routes.
Onboarding Preferences Schema: profiles.preferences is a JSON column. Shape: { preferredIDE, languages[], workflow, learningTrack, primaryGoal }. learningTrack values: web-dev | backend | cs-fundamentals | mobile | data. primaryGoal values: get-a-job | build-project | pass-bootcamp | learn-for-fun. Can power roadmap template auto-selection.
Inngest (installed, not integrated): Inngest is in package.json but zero functions are wired. It's the correct tool for webhook retry queues and post-session notifications (SM-2 reminders). Integration is a P2 priority — it would eliminate Bug B1 (webhook silent failures) entirely.
Stale .next Cache: If the app returns 500 with "React Client Manifest" errors after code changes, delete the .next folder and restart the dev server. This is a Turbopack known issue with certain file structure changes.
