## Anti-Patterns Verdict

**LLM assessment:**

The hero section is genuinely strong. The asymmetric split-screen with the dark dashboard mockup, the live-updating timer, and the mint headline accent are all intentional and on-register. The `COMMIT_` logo with its blinking cursor is a deliberate brand signal.

But three AI tells fire immediately on deeper inspection:

1. **The kicker reflex.** Every section opens with `// features`, `// how it works`, `// pricing`, etc. in JetBrains Mono. This pattern is on the absolute ban list verbatim: "Tiny uppercase tracked eyebrow above every section." It's the most saturated AI scaffold in landing page generation right now. The design system's own Label Scarcity Rule says "one per section as orientation" — but here every section fires one, which collapses the rule into noise.

2. **Space Grotesk on the reflex-reject list.** The font chosen for the brand's headings appears explicitly on brand.md's reflex-reject list. This is a training-data default. It's not wrong per se — it's a clean font — but it's the saturated choice, and the critique requirement is distinctiveness.

3. **The ambient green glow.** The hero has a large radial gradient mint glow behind the content. The design system's No Ambient Shadow Rule prohibits this ("No ambient glow under buttons. No diffuse outer glows"). The CTA section repeats the same large bloom. Using the accent color as atmospheric fill directly contradicts the Rarity Rule ("Precision Mint at full opacity is permitted only when it carries active or completion state, a live measurement, or the single primary CTA per view").

**Deterministic scan:** The automated detector (`detect.mjs --json app/page.tsx`) returned zero findings. No side-stripe borders, no gradient text, no glassmorphism. The absolute-ban patterns at code level are clean.

**Visual overlays:** Browser injection was not re-run in this pass. The full-page screenshot (`critique-full.png`) confirmed the major P0 finding visually: after the hero section, the entire page body renders as solid black in a screenshot context. The content gating bug is visually confirmed.

## Overall Impression

The hero works. The overall product concept is communicated clearly and the design avoids the worst dark-SaaS clichés. But the page ships with a showstopper: `opacity: 0` on `.reveal` elements means any non-interactive renderer (screenshots, SEO crawlers, social card generators, headless browsers, users who open the page in a background tab) sees a blank page below the fold. This needs to be fixed before anything else is discussed. After that, the font and kicker pattern are the two highest-leverage design improvements.

## What's Working

**1. Hero composition.** The asymmetric split-screen with the floating dashboard mock is a deliberate choice, not a default. The live timer ticking in the mockup creates genuine product presence. The headline "Stop re-learning the same thing twice" is concrete, not buzz-wordy.

**2. The design system itself.** The DESIGN.md rules are well-formed: the Rarity Rule, Tonal Depth Rule, No Ambient Shadow Rule, Label Scarcity Rule — these are real design constraints, not vague principles. The problem is that the implementation violates several of them.

**3. Copy.** "Stop re-learning the same thing twice" and "The workspace that actually builds your knowledge, not just your streak count" are specific, anti-gamification, and on-brand. The copy avoids the empower/streamline/unlock family of clichés.

## Priority Issues

**[P0] Content gating: entire page invisible in non-interactive contexts**
- **What**: Every section below the hero uses `.reveal`, `.reveal-left`, or `.reveal-right` classes that start at `opacity: 0`. The `.is-visible` class is added by an `IntersectionObserver` in `useScrollReveal()`. In any context where that observer doesn't fire — headless screenshots, social card generators, SEO crawlers, background tabs, reduced-motion users who have JS disabled, users on very slow connections — the page below the fold is completely invisible.
- **Why it matters**: The full-page screenshot confirms this is not theoretical. The page literally looks blank from the hero fold down. Google's crawler and social card generators will see a blank page. New users who open the tab in the background will see a broken experience.
- **Fix**: Reveal animations must enhance an already-visible default, not gate visibility. Remove `opacity: 0` as the default state. Instead, add `@starting-style` or use JavaScript to add an `.animations-ready` class to `<html>` only after JS loads, and scope the `opacity: 0` initial state inside `.animations-ready .reveal { opacity: 0; }`. The fallback (no `.animations-ready` class) should show all content normally.
- **Suggested command**: `/impeccable animate app/page.tsx` (restructure the reveal system)

**[P0] No reduced-motion support**
- **What**: `globals.css` contains no `@media (prefers-reduced-motion: reduce)` block. The `useScrollReveal`, `useMagnetic`, `useTilt`, `useSpotlight`, and `gentleFloat` / `timerPulse` / `cellPop` CSS animations all fire for every user regardless of system preference.
- **Why it matters**: PRODUCT.md explicitly lists "Reduced motion support required: all animations must degrade gracefully" under Accessibility & Inclusion. This is a self-stated accessibility violation. Users with vestibular disorders who have set reduce-motion in their OS get the full animation suite anyway.
- **Fix**: Add to `globals.css`: `@media (prefers-reduced-motion: reduce) { .reveal, .reveal-left, .reveal-right { opacity: 1; transform: none; transition: none; } .animate-breathe, .animate-breathe-slow { animation: none; } }`. Also add reduced-motion guards in the JS hooks: check `window.matchMedia('(prefers-reduced-motion: reduce)').matches` before attaching mousemove and RAF-based animations.
- **Suggested command**: `/impeccable audit app/page.tsx` (accessibility pass)

**[P1] Space Grotesk is on the brand reflex-reject list**
- **What**: `app/layout.tsx` loads Space Grotesk as `--font-display`. `brand.md`'s reflex-reject list explicitly includes "Space Grotesk" as a training-data default to ban.
- **Why it matters**: The identity of the brand's display type is its first impression. Space Grotesk is a clean, competent font. It is also the saturated AI-default geometric sans that appears on roughly half of all AI-generated dark SaaS pages built in 2024-2025. It does not differentiate Commit.
- **Fix**: Replace with a font not on the reflex-reject list. For Commit's brand voice (precise, understated, tool-as-instrument): candidates worth evaluating include **Geist** (Vercel's custom font, free), **Neue Haas Grotesk / Aktiv Grotesk** (licensed), or **Manrope** (open, geometric but less saturated). The bar is: "would someone guess Space Grotesk from the brief?" If yes, find a different answer. Changing one variable in `layout.tsx` is a low-cost, high-identity-impact move.
- **Suggested command**: `/impeccable typeset app/page.tsx`

**[P1] Monospace kicker on every section — absolute ban violated**
- **What**: Six sections each open with a JetBrains Mono kicker (`// features`, `// how it works`, `// pricing`, `// faq`, etc.). The impeccable skill's absolute ban list states verbatim: "Tiny uppercase tracked eyebrow above every section." The design system's own Label Scarcity Rule states: "Monospace uppercase labels are permitted once per section as orientation. A kicker on every card is noise, not system."
- **Why it matters**: The kicker is the most recognizable AI scaffold on landing pages right now. When it appears on every section, it broadcasts "AI wrote this" louder than any single element on the page. It also kills hierarchy: if every section announces itself with the same mono label, none of them do.
- **Fix**: Remove the kicker from at least 4 of the 6 sections. Keep it on one or two sections where the label genuinely provides orientation (perhaps `// pricing` where the context shift is real). Replace section openings with the headline directly, or with a structural divider. The absence of the kicker reads as more confident.
- **Suggested command**: `/impeccable quieter app/page.tsx`

**[P2] Ambient green glow violates The No Ambient Shadow Rule and The Rarity Rule**
- **What**: The hero section renders a large radial gradient mint bloom (`rgba(0, 255, 170, 0.15)`) as an atmospheric background. The CTA section near the bottom renders an even larger version. These are decorative accent washes, not active/completion state markers.
- **Why it matters**: DESIGN.md's No Ambient Shadow Rule says "No ambient glow shadows under buttons. No diffuse outer glows." The Rarity Rule says Precision Mint "at full opacity is permitted only when it carries active or completion state, a live measurement, or the single primary CTA per view." A background atmospheric bloom is neither. It also weakens the accent's signal value: if mint fills the air, it no longer marks what's live or active.
- **Fix**: Remove the background radial gradient blooms from both the hero and CTA sections. The dark void surface communicates depth without glow. The mint accent earns its power from rarity; give it back. If a visual anchor is needed in the hero, the dashboard mock itself provides it.
- **Suggested command**: `/impeccable quieter app/page.tsx`

## Persona Red Flags

**Jordan (First-Timer — landing page primary persona):**
Jordan lands on the hero and reads "Stop re-learning the same thing twice." She doesn't yet know what that means. She scrolls. If her browser tab was opened in the background (common on mobile), she sees a completely black page. She thinks the site is broken and leaves. Even in the best case (interactive foreground tab), she scrolls through 6 sections each opened with `// features` / `// how it works` in small monospace — this reads as "developer inside baseball," not a beginner-friendly invitation. The three pain points in the Why section ("Starting strong but losing momentum after week 2") are written for her, but she has to get there. The content gating is the abandonment trigger.

**Riley (Stress Tester — landing page secondary persona):**
Riley opens the page in a new background tab while reading something else. She switches to the tab after 30 seconds. The IntersectionObserver never fired because the tab was hidden when the elements entered the viewport. She sees the hero, then black. She tries scrolling — nothing. She refreshes. Now it works because she's in the foreground. She files a "blank page on first visit" bug report. The intermittent nature makes it harder to reproduce, so it goes unfixed.

**Casey (Mobile User — landing page tertiary persona):**
Casey opens the link on her phone from a Twitter/X post. The page loads, she sees the hero, she scrolls fast. The `.reveal` animations fire one by one as she scrolls, which on a mid-range Android (Snapdragon 695, no will-change optimization on these elements) creates visible jank — content pops in with a 700ms spring easing that reads as "loading slowly." No `@media (prefers-reduced-motion)` means even if she's turned off animations in system settings, the full animation suite fires. The ambient green glow in the hero renders as a large GPU-composited layer on mobile, adding to paint cost.

**Dev Student (Project-specific persona — from PRODUCT.md):**
A CS student who found Commit through a GitHub trending page. They're technically literate — they recognize JetBrains Mono, they understand what SM-2 means, they can evaluate the Pomodoro feature. But they're evaluating three or four productivity tools this week. They land on the page and their first gut read is: "another AI-generated SaaS page with Space Grotesk and eyebrow labels." They're not wrong. The distinctive features (Flashcards with SM-2 ratings, the Commit Prompt, the Bug Journal) are all there in the copy, but they don't stand out from the ambient noise of the page's AI tells. The font and kicker pattern make the product feel less serious than it is.

## Minor Observations

- `text-wrap: balance` is not applied to the hero h1. At certain viewport widths the headline wraps awkwardly ("Stop re-learning / the same thing / twice.").
- The pricing toggle (Monthly / Annual) has no animation showing the price transition. The numbers change instantly, which feels abrupt for an interactive element.
- The FAQ accordion expands/collapses but has no `aria-expanded` attribute, making it inaccessible to screen reader users.
- The `HEATMAP_INTENSITIES` static array (used to avoid SSR hydration mismatch — correct) produces an identical heatmap pattern for every user. Real users would notice the pattern never changes.
- The `useCounter` hook animates numbers from 0 to the target. On the "Stats" section, numbers like "11" and "25" animate from 0 in 1400ms. This is longer than it needs to be for small numbers; 800ms would feel more precise.
